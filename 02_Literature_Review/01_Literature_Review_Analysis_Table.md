# Literature Review Analysis Table

| No. | Author(s) | Year | Research Problem | Method / Technique | Dataset / Data Source | Main Findings | Limitation | Relevance to Proposed Research |
|---|---|---:|---|---|---|---|---|---|
| 1 | Kini et al. | 2022 | Difficulty detecting SQL Injection attacks using conventional pattern-based techniques. | Aho-Corasick pattern matching algorithm with predefined SQLi patterns. | 860 malicious SQL injection query patterns tested on a custom-built website. | Achieved 90.23% detection accuracy and detected major SQLi types including Boolean, Error, Time and Union-based attacks. | Relies on a static pattern list and may not detect new or modified SQLi payloads. | Provides a traditional detection baseline and demonstrates the limitation of fixed patterns, supporting the use of ML-based detection. |
| 2 | Ibrohim & Suryani | 2023 | Difficulty accurately classifying malicious SQL injection queries from legitimate queries. | TF-IDF with SVM and Naïve Bayes using a voting ensemble. Preprocessing included duplicate removal, oversampling, case folding and tokenization. | SQL injection query dataset. | Achieved 92.9% accuracy using the ensemble learning approach. | Performance depends on dataset quality and fixed TF-IDF feature representation. | Demonstrates the effectiveness of ML-based SQLi classification and supports further testing of ML models across different datasets. |
| 3 | Okesola et al. | 2023 | Risk of SQL injection attacks in web applications caused by unsafe handling of user input. | Parameterised queries for SQL injection prevention. | Web application SQL query context and parameterised query implementation. | Parameterised queries help separate SQL commands from user input and reduce SQL injection risks. | Primarily focuses on prevention rather than ML-based detection and does not evaluate cross-dataset model generalisation. | Provides a traditional prevention baseline and shows the importance of automated detection as a complementary security approach. |
| 4 | Shah et al. | 2024 | Need to accurately classify malicious SQLi code using machine learning. | Extra Trees for selecting 25 important features followed by Random Forest ensemble classification. | Kaggle SQL query logs. | Random Forest achieved 98.9% accuracy. | Evaluation is mainly based on one dataset, providing limited evidence of performance on other datasets. | Highly relevant because it directly applies Random Forest to SQLi classification and supports testing Random Forest across different datasets. |
| 5 | Falowo et al. | 2025 | Need for reliable detection and classification of SQL injection attacks using ML. | Stacking ensemble using Decision Tree, Random Forest and Logistic Regression as base learners with a meta-classifier. | Approximately 33,000 SQL queries. | The stacking model demonstrated strong SQLi detection and classification performance while balancing precision and recall. | Multiple models and a meta-classifier increase complexity and processing requirements. | Shows the usefulness of Random Forest in SQLi detection while motivating a simpler single-model Random Forest approach. |
| 6 | Pansare et al. | 2025 | Need to identify malicious SQL queries using machine learning. | TF-IDF feature extraction with XGBoost classification. | 30,000 SQL queries: 15,000 benign and 15,000 malicious. | Achieved 99.37% accuracy, 99.41% precision, 99.31% recall and 99.36% F1-score. | Evaluation uses a specific balanced dataset, so performance may differ on datasets with different distributions and attack characteristics. | Demonstrates high ML performance on a specific dataset and supports the need for cross-dataset evaluation. |
| 7 | Hosen et al. | 2026 | Need for lightweight and interpretable SQLi detection with reliable external evaluation. | TF-IDF with Decision Tree and SHAP for model interpretation. | Hybrid synthetic and real-world SQLi datasets with external Kaggle testing. | Achieved 98.31% training accuracy and 97.52% external accuracy with low latency and interpretable SHAP results. | Limited coverage of complex SQLi payloads and requires further testing in more diverse environments. | Demonstrates the importance of external dataset testing and supports evaluating model generalisation beyond the training dataset. |
| 8 | Toktassyn & Al-Hubaishi | 2026 | Need to improve SQLi detection using advanced features and ML models. | Statistical, syntactical and entropy-based features with TF-IDF; comparison of eight ML models including Random Forest. | IEEE DataPort dataset with 244,068 queries: 136,740 malicious and 107,328 legitimate. | Random Forest achieved 99.3% accuracy on an 80:20 split and 99.1% on a 50:50 split. | Uses one dataset; adversarial attacks and real-world deployment were not evaluated. | Highly relevant because Random Forest achieved strong performance but was mainly evaluated on one dataset, supporting cross-dataset evaluation. |
