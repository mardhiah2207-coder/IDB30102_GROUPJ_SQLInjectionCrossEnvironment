# Literature Review Analysis Table

| No. | Author(s) | Year | Research Problem | Method / Technique | Dataset / Data Source | Main Findings | Limitation | Relevance to Proposed Research |
|---|---|---:|---|---|---|---|---|---|
| 1 | Kini et al. | 2022 | Difficulty detecting SQL Injection attacks using conventional pattern-based techniques. | Aho-Corasick pattern matching algorithm with predefined SQLi patterns. | 860 malicious SQL injection query patterns tested on a custom-built website. | Achieved 90.23% detection accuracy and detected major SQLi types including Boolean, Error, Time and Union-based attacks. | Relies on a static pattern list and may not detect new or modified SQLi payloads. | Provides a traditional detection baseline and demonstrates the limitation of fixed patterns, supporting the use of ML-based detection. |
| 2 | Arif et al. | 2022 | Need to detect and prevent SQL Injection attacks against MySQL databases. | Input Categorization with Input Verifier, supported by automatic and manual SQLi testing. | 15 web applications with five different database characteristics; tested using SQLMap, PHP, MySQL and localhost. | Applications using the detection and prevention technique resisted the tested Union-based, Error-based and Blind SQLi attacks. | Only one detection and prevention technique was studied and the evaluation covered limited SQLi types. | Provides a traditional input validation and verification baseline for comparison with ML-based detection. |
| 3 | Qbea’h et al. | 2022 | Need to understand why SQL Injection remains a threat despite the availability of mitigation approaches. | Literature review comparing SQLi types and static, dynamic and machine learning-based mitigation methods. | Previous SQL Injection studies and security tools including SQLBlock, DIAVA, SQLMap and Acunetix. | Identified six major SQLi types and showed that existing ML techniques and security tools may not cover all attack types. | Review indicates that many existing tools are focused on specific environments, while manual and modified attacks remain difficult to detect. | Supports the need for more comprehensive detection approaches and evaluation across different datasets and environments. |
| 4 | Muliono et al. | 2022 | Need to predict the confidentiality, integrity and availability impact of SQL Injection payloads for SIEM prioritisation. | SVM classifier integrated with SIEM; preprocessing included tokenization and Bag-of-Words. | CSIC 2010 dataset and SQLMap payloads. | Achieved more than 94% accuracy in classifying SQLi attack types and intentions. | Performance depends on the quantity and quality of training data and processing integrity. | Demonstrates the application of ML to SQLi classification and highlights the importance of dataset quality in model performance. |
| 5 | Zhang et al. | 2022 | Difficulty detecting SQL Injection statements and reducing dependence on manual feature extraction. | SQLNN deep neural network using word-vector representation, sparse matrices, multiple hidden layers, ReLU and Dropout. | Kaggle SQL Injection dataset containing 30,919 SQL statements. | The proposed model maintained accuracy above 96% and outperformed KNN, Decision Tree and LSTM using Accuracy, Precision, Recall and F1-score. | Evaluation is based mainly on one dataset, providing limited evidence of performance across different datasets. | Demonstrates strong ML/DL performance on one dataset and supports the need to evaluate detection models across different datasets. |
| 6 | Ibrohim & Suryani | 2023 | Difficulty accurately classifying malicious SQL injection queries from legitimate queries. | TF-IDF with SVM and Naïve Bayes using a voting ensemble. Preprocessing included duplicate removal, oversampling, case folding and tokenization. | SQL injection query dataset. | Achieved 92.9% accuracy using the ensemble learning approach. | Performance depends on dataset quality and fixed TF-IDF feature representation. | Demonstrates the effectiveness of ML-based SQLi classification and supports further testing of ML models across different datasets. |
| 7 | Okesola et al. | 2023 | Risk of SQL injection attacks in web applications caused by unsafe handling of user input. | Parameterised queries and prepared statements for SQL Injection prevention. | E-commerce application prototype using Java servlets and SQL. | The application was protected from the tested SQLi attacks because user input was treated strictly as data, with no significant runtime performance impact. | Primarily focuses on prevention rather than ML-based detection and does not evaluate cross-dataset model generalisation. | Provides a traditional prevention baseline and shows the importance of automated detection as a complementary security approach. |
| 8 | Bouafia et al. | 2023 | Need to practically identify and exploit SQL Injection vulnerabilities in web applications. | Automated penetration testing using Acunetix, Burp Suite and SQLMap through scanning, interception, command generation and exploitation. | Damn Vulnerable Web Application (DVWA). | SQL Injection exploitation was successful at low, medium and high security levels; SQLMap was also able to extract information and decrypt MD5 hashes. | Evaluation focused on DVWA and automated penetration testing, limiting evidence across other applications and environments. | Provides a practical security testing baseline and demonstrates that SQLi vulnerabilities can remain exploitable despite application hardening. |
| 9 | Shah et al. | 2024 | Need to accurately classify malicious SQLi code using machine learning. | Extra Trees for selecting 25 important features followed by Random Forest ensemble classification. | Kaggle SQL query logs. | Random Forest achieved 98.9% accuracy. | Evaluation is mainly based on one dataset, providing limited evidence of performance on other datasets. | Highly relevant because it directly applies Random Forest to SQLi classification and supports testing Random Forest across different datasets. |
| 10 | Zulu et al. | 2024 | Need to improve SQL Injection detection through better representation of SQL query information. | Contextualized and non-contextualized word embeddings evaluated with neural networks, KNN, Random Forest and Logistic Regression. | SQL Injection query dataset used for evaluating different embedding and classification combinations. | Contextualized embeddings achieved accuracy above 99% across classification algorithms and reduced model training time by approximately 31 times. | The study focuses strongly on embedding representation and model training rather than cross-dataset generalisation. | Shows that feature representation can affect ML-based SQLi detection and provides evidence that Random Forest can be evaluated with different query representations. |
| 11 | Falowo et al. | 2025 | Need for reliable detection and classification of SQL injection attacks using ML. | Stacking ensemble using Decision Tree, Random Forest and Logistic Regression as base learners with a meta-classifier. | Approximately 33,000 SQL queries. | The stacking model demonstrated strong SQLi detection and classification performance while balancing precision and recall. | Multiple models and a meta-classifier increase model complexity and processing requirements. | Shows the usefulness of Random Forest in SQLi detection while motivating a simpler single-model Random Forest approach. |
| 12 | Pansare et al. | 2025 | Need to identify malicious SQL queries using machine learning. | TF-IDF feature extraction with XGBoost classification. | 30,000 SQL queries: 15,000 benign and 15,000 malicious. | Achieved 99.37% accuracy, 99.41% precision, 99.31% recall and 99.36% F1-score, with prediction time under 100 ms. | Evaluation uses a specific balanced dataset, so performance may differ on datasets with different distributions and attack characteristics. | Demonstrates high ML performance on a specific dataset and supports the need for cross-dataset evaluation. |
| 13 | Hosen et al. | 2026 | Need for lightweight and interpretable SQLi detection with reliable external evaluation. | TF-IDF with Decision Tree and SHAP for model interpretation. | Hybrid synthetic and real-world SQLi datasets with external Kaggle testing. | Achieved 98.31% training accuracy and 97.52% external accuracy with low latency and interpretable SHAP results. | Limited coverage of complex SQLi payloads and requires further testing in more diverse environments. | Demonstrates the importance of external dataset testing and supports evaluating model generalisation beyond the training dataset. |
| 14 | Toktassyn & Al-Hubaishi | 2026 | Need to improve SQLi detection using advanced features and ML models. | Statistical, syntactical and entropy-based features with TF-IDF; comparison of eight ML models including Random Forest. | IEEE DataPort dataset with 244,068 queries: 136,740 malicious and 107,328 legitimate. | Random Forest achieved 99.3% accuracy on an 80:20 split and 99.1% on a 50:50 split. | Uses one dataset; adversarial attacks and real-world deployment were not evaluated. | Highly relevant because Random Forest achieved strong performance but was mainly evaluated on one dataset, supporting cross-dataset evaluation. |
